# 슬라이드별 리뷰 작성 규칙

이 문서는 사람과 사내 모델이 함께 쓸 검토 안내입니다. 정확한 필드 계약은 추출 run 안의 `REVIEW_GUIDE.md`와 해당 버전의 검증기입니다. `review.schema.json`은 최소 구조 안내이며 의미 검증 도구가 아닙니다.

## 필수 확인 단위

각 슬라이드에 문서 해시, 실제 순번, 원본 XML 파트, 숨김 여부, 원문 전문 링크, 발표자 노트, 전체 렌더 링크를 연결합니다. 노트에는 다음을 기록합니다.

1. 원문에서 확인한 주장과 주장 ID.
2. 수치·단위·부호·범위·축·범례·기준값·조건·예외·각주.
3. 이미지에서 직접 관찰한 사실, 그로부터의 해석, 확인하지 못한 부분.
4. 원문과 노트의 대응 locator. 의미를 묶어 설명하더라도 원문 단락/표 셀을 잃지 않습니다.
5. 검토자/실제 모델 이름, 검토 시각, 검토한 이미지 경로와 영역, 남은 불확실성.

`slides/slide-NNNN.json`의 `text_records[].locator`를 복사합니다. `ppt/slides/slide7.xml#p:00001`처럼 내부 파일의 숫자는 실제 슬라이드 순번과 다를 수 있습니다. **순번은 manifest의 slide_no가 기준**입니다.

## review.json 예시

아래는 형식을 설명하기 위한 **가상 예시**이며 사내 DRAM 사실이 아닙니다. 실제 원문이 이 문자열을 포함하지 않으면 검증에 실패합니다. 해당 run의 자동 생성 구조를 바탕으로 채우세요.

```json
{
  "slide_no": 1,
  "status": "reviewed",
  "reviewer": "실제 검토한 사내 모델 또는 사람 식별자",
  "reviewed_at": "2026-10-26T09:30:00+09:00",
  "claims": [
    {
      "id": "S001-C001",
      "text": "원문은 시험 조건에서 1.20 V를 명시한다.",
      "claim_type": "text",
      "evidence": [
        {
          "kind": "pptx_text",
          "locator": "ppt/slides/slide7.xml#p:00001",
          "quote": "1.20 V"
        }
      ],
      "numbers": [
        {
          "verbatim": "1.20 V",
          "value": "1.20",
          "unit": "V",
          "conditions": "원문에 적힌 조건을 그대로 기재; 없으면 미명시",
          "source_locator": "ppt/slides/slide7.xml#p:00001",
          "checked": true
        }
      ]
    }
  ],
  "numbers": [],
  "figure_interpretations": [
    {
      "asset_path": null,
      "method": "unavailable",
      "description": "렌더 이미지 입력이 지원되지 않아 도표를 해석하지 못함",
      "uncertainties": ["도표의 축과 연결 관계 미확인"],
      "assessed_by": "실제 검토자",
      "scope": "whole_slide"
    }
  ],
  "uncertainties": ["이미지 기반 관계는 확인 불가; 텍스트 주장 범위로 제한"]
}
```

이 객체는 루트 `slides` 배열의 한 항목입니다. 루트 `schema_version: 1`과 모든 슬라이드 항목을 유지합니다. 숫자가 있는 주장에는 claim 내부 `numbers`를 채웁니다. 슬라이드 수준 `numbers`는 추가 정량 기록용입니다. 숫자가 없으면 빈 배열로 둡니다.

`value`, `unit`, `conditions`는 문자열입니다. 무차원/조건 미명시는 각각 `해당없음`, `미명시`로 명시합니다. 의미를 모르면서 `checked: true`를 넣지 않습니다. 확인 못 한 숫자는 확정 주장으로 올리지 않고 원문과 미확인 목록에 남깁니다. 원문과 정확 표기가 다른 변환값은 원문 숫자처럼 등록하지 않습니다.

## 원문·OCR·Vision·추론 구분

- `pptx_text`: 슬라이드 또는 관련 XML에서 추출한 정확한 문자열. 캐시된 chart 값이 현재 화면과 일치하는지는 이미지로 대조합니다.
- `speaker_notes`: 발표자 노트 문자열. 본문에 적힌 사실과 혼동하지 않습니다.
- `ocr`: 로컬 OCR이 이미지에서 인식한 문자열. `quote`와 이미지 `locator`, `region`을 남깁니다. OCR 출력은 자동 정확도 보증이 아닙니다.
- `vision`: 실제로 이미지 입력을 열어 관찰한 내용. `locator`에 해당 슬라이드에 매핑된 이미지 경로, `region`에 좌표/영역 설명을 기록합니다. 파일이 있다는 이유만으로 쓰지 않습니다.
- `claim_type: visual`: 실제 vision 근거가 필요합니다. OCR만으로 이 유형을 통과시킬 수 없습니다.
- `claim_type: inference`: 문장에 `[추론]`을 넣고 관련 원문 근거와 불확실성을 기록합니다. 검증기는 계산의 정확성까지 증명하지 않습니다.

Vision 기록은 예를 들어 `asset_path: assets/slides/slide-0001.png`, `method: vision`, `scope: whole_slide`을 사용합니다. 실제 그림이 열렸는지, 사용한 모델/입력 경로, 관찰한 축·범례·연결·모양을 description에 구체적으로 남깁니다. OCR만 수행하면 `ocr_only`, 확인하지 못하면 `unavailable`입니다.

부분 그림을 확대해서 볼 때도 이 버전의 정식 근거 locator는 **등록된 전체 슬라이드 이미지 + region**을 사용합니다. 추가 크롭 파일은 보조 자료로만 사용하고 전체 그림과 bbox를 함께 기록합니다. 임의 크롭을 manifest의 원본 자산처럼 추가하거나 해시를 고치지 않습니다. 원시 media를 근거로 쓸 때는 해당 슬라이드 관계에 포함된 파일인지 먼저 확인합니다.

## 노트와 리뷰의 일치

검토가 끝나면 `notes/slide-NNNN.md`의 YAML `review_status`도 `reviewed`로 바꾸고, 주장마다 `S001-C001` 같은 ID와 근거를 적습니다. 검토 전 템플릿을 그대로 둔 채 JSON 상태만 바꾸지 않습니다. `reviewed`와 `미확인 있음`은 함께 성립할 수 있습니다.

슬라이드가 목차/빈 페이지처럼 기술 주장이 없으면 claims는 비울 수 있지만 이유를 uncertainties에 남기고 노트도 그 상태로 작성합니다. 그림 접근이 불가능하면 어떤 내용을 답할 수 없는지 노트와 리뷰 양쪽에 씁니다.

원문 전사에는 읽기 순서 차이, 텍스트로 추출되지 않는 수식/벡터/임베디드 데이터가 있을 수 있습니다. PPTX 전체와 패키지의 보존은 **바이트 보존**이며 모든 내용을 이해했다는 뜻이 아닙니다.

## 수치 및 조건 대조

- 숫자와 단위를 따로 바꾸지 않습니다. `μ`와 `m`, `ns`와 `ms`, `mV`와 `V`, 소수점·지수·상첨자·부호를 원문에서 확인합니다.
- 범위/부등호/평균·최대·최소/오차 막대/로그 축/정규화 기준을 보존합니다. 조건은 바로 옆 문장뿐 아니라 각주·앞뒤 슬라이드에 있을 수 있습니다.
- 그래프에서 읽은 값은 표기값인지 추정값인지 구분합니다. 추정 정밀도와 화면 영역을 남기며 원문에 없는 소수 자릿수를 늘리지 않습니다.
- 계산과 단위 환산은 입력 근거, 식, 반올림을 별도로 남깁니다. 이 버전의 정량 claim 검사는 원문에 있는 표기를 중심으로 하므로, 새로 계산한 수치를 원문 정량 claim으로 억지로 통과시키지 않습니다. 파생 계산은 Q&A 또는 별도 파생 노트에서 원문과 분리해 다룹니다.
- 조건과 단위의 의미적 일치는 수동 대조가 필요합니다. 검증기는 일부 텍스트/형식 일치만 검사합니다.

## 단계별 완료 기준

- A: 원본 사본 해시 일치, 전체 순번/숨김/객체 목록 확보.
- B: 렌더 매핑 대조, 실제 Vision 가능 여부 확인, 파일럿 비교 완료.
- C: 모든 슬라이드 노트·리뷰 기록, 중요 수치·조건·그림 연결 원문 대조.
- D: `validate --require-reviewed` 통과, 새 공개 인덱스에서 근거 링크 확인.

미확인/상충 항목은 완료 보고와 Q&A에서 계속 노출합니다. 같은 모델이 쓴 노트를 같은 모델이 검토한 경우 독립된 사람 검토를 받았다고 표현하지 않습니다.
